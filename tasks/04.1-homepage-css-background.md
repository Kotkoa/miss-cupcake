# Task 4.1: Homepage background in CSS instead of an image

Replace the three full-page background images (`bg-m.webp`, `bg-t.webp`, `bg-d.webp`) with CSS: colored bands per section and wavy edges between them.

## Problem

`src/pages/Home/Home.module.css` puts one tall image behind the whole page and stretches it with `background-size: 100% 100%`. This causes problems:

- **Bands drift from content.** The image stretches to page height, so when content is taller or shorter than in Figma (other fonts, wrapping, widths between breakpoints), the wave edges move relative to the sections.
- **Magic spacings.** Section paddings such as `340px` / `455px` (Cupcakes) and `212px` / `337px` (Once upon a time) exist only to line text up with the image's bands.
- **Waves distort.** `100% 100%` scales the waves differently on every screen width.
- **Colors live outside tokens.** Three bitmaps (50 KB) hold colors that are not in `tokens.css`.

## What the background is (measured from the exported images)

Five flat color bands, top to bottom; each edge between them is an irregular wave.

| # | Band | Color | Matches section | Desktop band y | Token |
|---|---|---|---|---|---|
| 1 | Pink | `#F7CFDA` | Header + Hero | 0–~700 | `--color-bg-home` (exists) |
| 2 | Yellow | `#FBF9CA` | Simple sweet life | ~700–~1740 | new (≈ `--color-on-primary` `#FBFAC9`) |
| 3 | Mint | `#EEFBE2` (Mobile `#F0FAE2`) | Cupcakes | ~1740–~4950 | new |
| 4 | Cream | `#FDEFD2` | Once upon a time | ~4950–~5900 | `--color-surface` (merged) |
| 5 | Purple | `#5E3295` | Footer | ~5900–end | ≈ `--color-overlay` base `#5D3394` |

Wave height (peak to trough): about **110px** on Desktop and Tablet; on Mobile **40–60px** for the upper edges and about 110px for cream → purple. The "Once upon a time" image overlaps the purple band in Figma, so the image sits on top of the edge.

## Proposed architecture

**Each section owns its band.** The page has no background; every section paints its own color, and the wavy edge belongs to the top of the next section.

```
<section class="band" style="--band-color: var(--color-band-yellow)">   ← SimpleLife
  ::before  = wave at the top edge, drawn in --band-color, overlapping the previous band
  content
</section>
```

```css
/* src/styles/band.css or a Band component */
.band {
  position: relative;
  background-color: var(--band-color);
}

.band::before {
  content: '';
  position: absolute;
  inset-inline: 0;
  bottom: 100%;               /* sits just above the section */
  height: var(--wave-height); /* 40-60px Mobile, 110px Tablet/Desktop */
  background-color: var(--band-color);
  mask: url('../assets/waves/wave-1.svg') bottom / 100% 100% no-repeat;
  pointer-events: none;
}
```

Why this way:

- **Color stays in tokens.** The SVG is only a **mask** (shape), so the color comes from `--band-color`. One wave file works for any color.
- **Bands follow content.** A section that grows makes its band grow; the wave stays at the section's top edge at any width.
- **Spacing becomes honest.** Section `padding-block` describes the space inside the band, not alignment with a bitmap.
- **Small files.** One or more SVGs of a few hundred bytes each, instead of 50 KB of images.

### Wave shapes

- Draw each edge as an SVG path with `viewBox="0 0 1440 110"` and `preserveAspectRatio="none"`, traced from the Figma background (node `2:5` on Desktop, `9:1057` Tablet, `9:1059` Mobile), or redrawn by hand as a close cubic-Bézier curve.
- Minimum: one wave shape reused for all four edges (flipped with `scale(-1, 1)` for variety). Full fidelity: four shapes, one per edge.
- On Mobile, `100% 100%` squeezes a 1440-wide wave into 375px, which makes it too dense. Use a separate narrower mask for Mobile, or `mask-size: 1440px 100%` with `mask-position: center` (crops instead of squeezing).

### Alternatives considered

| Option | Verdict |
|---|---|
| `mask` + pseudo-element (above) | **Recommended.** Shape and color are separate; pure CSS once the SVG exists. |
| Inline `<svg>` divider component with `fill="currentColor"` | Good too; slightly more markup; easier to animate. Pick if the mask has rendering issues. |
| `clip-path: path(...)` on the section | Rejected: `path()` uses absolute pixels and does not scale with width. |
| Only `radial-gradient` circles, no SVG | Possible as an exercise, but gives a regular sine-like wave, not the irregular edge from Figma. |
| Keep the bitmaps but switch to `background-size: 100% auto` per band | Rejected: still bitmaps, still not tied to sections. |

## Steps

1. Add tokens: `--color-band-yellow`, `--color-band-mint`, `--color-band-purple` (decide whether to merge with `--color-on-primary` / `--color-overlay` and note the decision in the "merged values" comment), plus `--wave-height` with Tablet/Desktop overrides.
2. Create the wave SVG(s) in `src/assets/waves/`.
3. Implement `.band` (shared CSS or a small `Band` component) and give each Home section its band color.
4. Wrap the Footer in the purple band on the Homepage.
5. Remove `bg-*.webp` and the `background-image` rules from `Home.module.css`.
6. Replace "background wave" magic paddings with paddings measured inside the band (Figma distance from the wave to the content).
