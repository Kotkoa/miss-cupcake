## ADR-1: Cart state

- **Decision:** **Jotai** (`yarn add jotai`), code in `src/features/cart/`:
  - `store.ts`: an explicit store `export const store = createStore()`, passed to `<Provider store={store}>` in `main.tsx`. The same store is used in tests and can be read outside React (`store.get` / `store.set`).
  - `atoms.ts`:
    - `cartItemsAtom = atomWithStorage<CartItem[]>('miss-cupcake:cart', [], undefined, { getOnInit: true })`, where `CartItem = { id: string; qty: number }`. `getOnInit` reads storage on first render, so the badge doesn't flash empty.
    - Derived read-only atoms: `cartLinesAtom` (items joined with `src/data/cupcakes.ts`: name, image, unit price, line total), `cartCountAtom`, `cartSubtotalAtom`.
    - Write-only action atoms: `addToCartAtom`, `setQtyAtom`, `removeFromCartAtom`, `clearCartAtom`.
  - `hooks.ts`, the only API components use: `useCartLines()`, `useCartCount()`, `useCartSubtotal()` (built on `useAtomValue`) and `useCartActions()` → `{ add, setQty, remove, clear }` (built on `useSetAtom`). Components never import atoms directly.
  - `cart.ts`: pure functions (`addItem`, `setItemQty`, …) that the action atoms call, so the logic is testable without React.
- Prices and names are never stored in the cart, only `{ id, qty }`.
- Persistence: `atomWithStorage` handles `localStorage` and syncs between tabs. Stored data is validated on read: unknown ids and non-positive or non-integer `qty` are dropped, and corrupt JSON falls back to `[]`.
- Unit price: **$3.49** for every cupcake (all line totals in Figma are multiples of 3.49). Store prices as integer cents (`349`) and format with `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`.
- Header badge = `cartCountAtom` (Figma "8" = 1 + 3 + 2 + 2). Badge hidden when the cart is empty.
- **Why Jotai:** atomic state means only the components that read an atom re-render (the badge doesn't re-render the page). Derived atoms replace selectors, `atomWithStorage` replaces hand-written persistence, and the API is small enough to learn alongside layout work.

## ADR-3: Popovers and modals

- My Bag: a non-modal popover anchored to the header cart (Desktop/Tablet); full-width sheet on Mobile if the Mobile frame shows it so. Closes on ×, Escape, outside click, and route change. Focus moves into it on open and back to the cart button on close.
- Confirmed: native `<dialog>` opened with `showModal()` (built-in focus trap, Escape, `::backdrop` with `--color-overlay`).
- No modal library.

## ADR-4: Forms and validation

- Native form + controlled inputs, validation in plain TypeScript functions (`src/features/checkout/validation.ts`); no form library (the point is to practise).
- Validate on blur and on submit; show errors with the shared `Input` `error` prop; focus the first invalid field on submit.
- Card data never leaves the browser: no network request, no storage, not logged. Only non-sensitive fields (name, email, address, delivery type) may be kept in `sessionStorage` so a reload doesn't wipe the form.

## ADR-5: Third-party media

- Video: self-hosted MP4 from Pixabay (free licence) in `public/media/`, native `<video controls preload="metadata">`; no player library.
- Map: **facade** pattern. A static map image with a pin and a "Show interactive map" button; the Google Maps `<iframe>` (no API key) replaces it only after the click. A "Open in Google Maps" link is always visible.
  - **Why:** an embed loads ~1 MB of third-party JS and sets Google cookies on page load. That hurts performance (Lighthouse) and needs consent under GDPR (the store is in Spain). It also hijacks scrolling on touch screens. With a facade, nothing is requested from Google until the user asks, and the click is the user's explicit choice.
  - **Rejected:** plain lazy `<iframe>` (still loads and sets cookies when scrolled near); Google Static Maps API (needs a key and billing); Leaflet + OSM (more work; keep as an option if an interactive map is wanted for practice).
  - Static image: OpenStreetMap export of the store area (openstreetmap.org → Share → Image), WebP, attribution "© OpenStreetMap contributors" shown on the image. The Figma map shows London, so it can't be reused.

## Acceptance criteria

- [x] `jotai` is in `dependencies`; the app is wrapped in `<Provider store={store}>` with the store from `src/features/cart/store.ts`.
- [x] Components use only the hooks from `src/features/cart/hooks.ts` (`useCartLines`, `useCartCount`, `useCartSubtotal`, `useCartActions`); no component imports atoms or calls `useAtom` directly.
- [x] Only `{ id, qty }[]` is persisted, under `miss-cupcake:cart`.
- [x] Cart survives a page reload with no empty-badge flash; corrupted or invalid `localStorage` data is ignored without a crash; a change in one tab shows up in another.
- [x] Re-render check (React DevTools Profiler): changing a quantity re-renders the badge and cart views, not the whole page.
- [x] Unit tests (Vitest): pure cart functions (add, increase, decrease to 0 removes the line, clear), atoms through `createStore()` (`store.set(addToCartAtom, …)` → `store.get(cartCountAtom)`, `cartSubtotalAtom` in cents), price formatting.
- [x] All routes from the table exist (pages may be empty placeholders until their task), plus 404.
- [x] Header badge shows the live count on every page.
- [x] `yarn build`, `yarn lint` and `yarn test` pass.
