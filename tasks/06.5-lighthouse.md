## Known limits

- **No-JS crawlers and link previews** (Slack, Telegram, Facebook, Twitter) see an empty `index.html`: no title, description or `og:*` tags. React 19 does not adopt a static `<title>`, so `index.html` carries none (a second `<title>` would be invalid, see 6.4); real previews need prerendering. Lighthouse and Google run the JS, so SEO is measured correctly.
- **LCP element on `/why-miss-cupcake`, `/checkout`, `/checkout/payment`**: a decoration picture on Mobile (Why: `decor-mobile`; Check out / Payment: `decor-m`) and the exploded cupcake / `decor-*` on Tablet and Desktop. They are eager (not lazy) but have no `fetchpriority` (Lighthouse notes it); LCP is 1.2 s mobile / 0.33 s desktop, so it was left. The Why page loads three decoration images at every width, because the unused ones are `display: none` and still eager; they are 10-44 kB.
- **Indexing**: `/checkout`, `/checkout/payment` and the 404 are indexable (no `noindex`). Not asked for; add `<meta name="robots" content="noindex">` in `PageMeta` if wanted.
- **`theme-color`** is the brand purple `#642c99` (browser UI on Android); the pages themselves are peach / pink. A design call, not a Lighthouse requirement.

## Deployment note (step 7)

The router is `BrowserRouter`, so the host must answer every path (`/our-story`, `/checkout/payment`, any 404 URL) with `index.html` and a 200: on Vercel a `vercel.json` with `{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }` (static files such as `/robots.txt`, `/favicon.ico` and `/assets/*` are served before rewrites). `yarn preview` already behaves that way. **The SEO 100 above was measured with a 200 fallback for every path** (`vite preview`, like the Vercel rewrite). A host that answers deep links with a real 404 (GitHub Pages with the `404.html` copy, task 7.0) can drop the `http-status-code` SEO audit: re-run this Lighthouse pass on the live URL and note it in 7.0. A client-rendered "Page not found" is a 200 for crawlers (soft 404); a real 404 status needs a server or prerender. `robots.txt` has no `Sitemap:` line because there is no production domain yet; add one then.
