# Task 6.5: Lighthouse check

Measure and fix performance, best practices and SEO on the **production build** (`yarn build && yarn preview`), never on `yarn dev`. Do last, after 6.0–6.4.

## Targets

| Category | Mobile | Desktop |
|---|---|---|
| Performance | ≥ 90 | ≥ 95 |
| Accessibility | 100 | 100 |
| Best Practices | ≥ 95 | ≥ 95 |
| SEO | ≥ 95 | ≥ 95 |

Core Web Vitals (lab, mobile): LCP ≤ 2.5 s, CLS ≤ 0.1, TBT ≤ 200 ms.

Routes: `/`, `/our-story`, `/why-miss-cupcake`, `/checkout` (with items), `/checkout/payment`.

## Known gaps to check first

- `index.html` has no `<meta name="description">` and no favicon (`public/` contains only `media/`). Add a description, favicon set (SVG + 180px apple-touch-icon), `theme-color`.
- No per-route meta: titles come from 6.4; add per-route descriptions in the same place.
- LCP image (hero cupcake on each page): `fetchpriority="high"`, not lazy, preloaded if Lighthouse asks; right size per breakpoint (`<picture>` already used: check the Mobile one isn't the Desktop file).
- Fonts: preload the Wendy One file used above the fold; `font-display: swap` (Fontsource default); check CLS from font swap.
- JS bundle is ~340 kB (115 kB gzip): lazy-load routes with `React.lazy` + `Suspense` (the `/ui` demo page is already removed in 6.0), check with `rollup-plugin-visualizer` or `vite build --report`.
- Video on Our Story: `preload="metadata"` only; it must not be the LCP element.
- Map facade: no Google requests until click (already required by 5.1; re-check).
- `robots.txt`; a SPA fallback note for deployment (step 7): all routes must serve `index.html`.

- [ ] Lighthouse (Chrome DevTools, mobile and desktop presets, incognito, `yarn preview`) meets the targets on all 5 routes; scores table with date in this file.
- [ ] LCP ≤ 2.5 s, CLS ≤ 0.1, TBT ≤ 200 ms on mobile for every route.
- [ ] Meta description, favicon set and `theme-color` added; each route has its own title and description.
- [ ] Routes are code-split: `/` doesn't load the code of other pages (e.g. Payment); bundle sizes before/after recorded here.
- [ ] Every image flagged by Lighthouse ("properly size", "next-gen format", "offscreen") fixed or explained.
