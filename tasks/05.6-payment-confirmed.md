# Task 5.6: Payment confirmed (modal)

Modal over `/checkout/payment`, opened by a valid "PLACE ORDER" (Task 5.5). Frames: Desktop `9:917` (also `839:215`), Tablet `30:235`, Mobile `31:846`. Requires ADR-3.

## What it shows

- Purple scrim over the page (`--color-overlay`, 70%).
- Popup (545×674 on Desktop): close ×, title "Your order is Confirmed!", text "Your order will be delivered within an hour.", button "DONE"; the bottom half is pink with a wavy edge and a cupcake illustration (layer "Gif Placeholder", so the design expects an **animated** image).

## Decisions (defaults)

- Native `<dialog>` + `showModal()`; title is the dialog's accessible name (`aria-labelledby`).
- On open: **cart is cleared**, the checkout form's `sessionStorage` is wiped.
- "DONE" → navigate to `/`. × or Escape → also go to `/` (the order is placed, so staying on an emptied payment page makes no sense).
- Illustration: export from Figma as a static WebP. If you want animation, use a looping WebP/GIF ≤ 300 KB or a small CSS animation (gentle bounce) and switch it off under `prefers-reduced-motion`.
- The popup's wavy edge reuses the band/wave technique from Task 4.1.

## Acceptance criteria

- [x] Opens only after a valid submit; the page behind is inert (no Tab into it, no scroll).
- [x] Focus starts in the dialog (on "DONE"); Escape, × and "DONE" all close it and go to `/`.
- [x] After closing: cart empty, badge hidden, checkout form data gone; Back button doesn't reopen the modal.
- [x] Scrim color and opacity match Figma; popup size and position match on Desktop/Tablet; Mobile matches `31:846`.
- [x] Animation (if any) respects `prefers-reduced-motion`.
- [x] Copy has fixed typos (ADR-6).
- [x] Manual test (agent, Chrome at 375 / 960 / 1440): full flow Homepage → add items → My Bag → Checkout → Payment → Confirmed → Home; keyboard-only run; console clean; **Test report** appended.
- [x] `yarn build` and `yarn lint` pass.

## Out of scope

Homepage "Registered completed" state (step 6); emails or order history.
