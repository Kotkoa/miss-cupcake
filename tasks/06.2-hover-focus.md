# Task 6.2: Hover and focus states

Figma draws **no** hover, focus, active or disabled states. Today they are ad hoc (opacity 0.85 on buttons, 0.7 on the cart and nav, a global outline). Goal: one small, consistent system for every interactive element.

## Proposed system (adjust once, then apply everywhere)

| State | Rule |
|---|---|
| Hover (filled button) | Background one step darker/lighter via a token (`--color-primary-hover`), no opacity (opacity also fades the text and hurts contrast) |
| Hover (text link, nav, footer link) | Underline (`text-decoration-thickness: 2px; text-underline-offset: 4px`) |
| Hover (icon button: cart, ×, stepper −/+, burger) | Soft circle/rounded background behind the icon (`--color-hover-surface`) |
| Active (pressed) | `transform: translateY(1px)` on buttons |
| Focus | `:focus-visible` only: 2px outline + 2px offset, color by surface (`--color-focus` on light, `--color-focus-on-dark` on purple bands) |
| Disabled / `aria-disabled` | `--opacity-disabled: 0.5`, `cursor: not-allowed`, no hover effect |
| Transitions | 150ms ease on color/background; none under `prefers-reduced-motion: reduce` |

- Hover styles only inside `@media (hover: hover)`, so touch screens don't get stuck hover.
- All new values are tokens in `tokens.css`.

## System as built

Deviations from the proposal table are marked **(+)**.

| State | Rule | Where |
|---|---|---|
| Hover, filled / light button | fill one step darker: `--color-primary-hover` `#4e2277`, `--color-surface-hover` `#fce6b6`; no opacity | `Button.module.css` |
| Hover, links | underline 2px, offset 4px (`base.css`); the text button ("View cart") gets the same; filled buttons that are `<a>` never underline | `base.css`, `Button.module.css` |
| Hover, icon buttons | `--color-hover-surface` (purple 12%) behind the icon; **(+)** `--hover-halo` grows it 4-8px past the box for the small targets (cart, burger, My Bag ×); on the purple notice bar `--color-hover-surface-on-dark` | `styles/interaction.module.css` (class `iconButton`, added in the TSX), `NoticeBar.module.css` |
| Active | `translate: 0 1px` (**(+)** `translate`, not `transform`, so buttons that already have a `transform` keep it) | buttons, icon buttons |
| Focus | `:focus-visible` only, 2px + 2px offset (was 4px). **(+)** the color is one variable, `--focus-color`: purple by default, cream inside `Band purple` and `NoticeBar`, purple again inside the map box (a light image on a purple band). All per-component overrides (Footer, Input, Button.light, NoticeBar, map link) are gone | `base.css`, `Band`, `NoticeBar`, `MapFacade` |
| Disabled / `aria-disabled` | `--opacity-disabled: 0.5` (the stepper used 0.35), `cursor: not-allowed`, no hover, no active | `Button`, `QuantityStepper` |
| Transitions | `--duration-fast: 150ms`, 0ms under `prefers-reduced-motion: reduce` (one token override, no `!important`) | `tokens.css` |

Other changes: the old global `border-radius` on every `:focus-visible` is now only on `a:focus-visible` (it was turning round buttons into 8px boxes on focus); the radio inputs and the × buttons are `border-radius: 50%`; NoticeBar centres its × with `inset-block: 0; margin-block: auto` (no `transform`); the footer heading link has `align-self: flex-start` (its ring spanned the whole column).

## Test report

Chrome (headed, relay), dev server, 1440 and 375 (+ 960 for the footer link box).

- **Forced states:** every row of the inventory above was read with `CSS.forcePseudoState`; the numbers in the "System as built" table are what the computed styles showed (for example Shop now: hover `rgb(78, 34, 119)`, focus `2px solid rgb(100, 44, 153)` offset 2px, active `translate: 0 1px`; footer: focus `2px solid rgb(253, 239, 209)`). Screenshots (forced state, 2x) are in `tasks/screenshots/06.2-*.png`: nav link hover, cart hover / focus, Shop now hover / focus on pink / active, stepper + hover, stepper − disabled, add to cart focus on mint, footer send hover, footer link focus / hover on purple, footer input focus, CTA focus on cream, video focus, Google Maps link hover, notice × hover / focus, radio hover / focus, and `06.2-map-button-focus.png` (after the fix: purple ring visible on the map; with the cream ring it was invisible).
- **Found in code review and fixed:** a focused `aria-disabled` stepper drew its ring at 50% opacity (opacity was on the button; now only the icon fades, ring is full strength, checked with forced `:focus-visible` + `:hover`: icon opacity 0.5, no hover background, `not-allowed`); the Confirmed × ring was clipped at the panel's top edge (ring now inside the button, `outline-offset: -2px`, checked on a screenshot of the open dialog); the 1px press offset is now `--press-offset`; the map ring offset uses `--focus-width`.
- **Found and fixed while testing:** the cream ring on "Show interactive map" was invisible on the light map; the footer heading link's ring spanned the whole column; the old global `border-radius` on `:focus-visible` turned round buttons square on focus.
- **Mouse vs keyboard:** a real mouse click on "add to cart" and on a stepper "+" leaves `:focus-visible` false and `outline-style: none`; Tab to the next button gives `:focus-visible` true, `solid`.
- **Tab through pages:** Home 1440 (48 stops) and 375 (46), Our Story 1440 (21), Why 1440 (14), Checkout 1440 (15), Payment 1440 (30) and 375 (27), 404 at 375 (3). Every stop has a visible 2px solid outline, except the `<video>` whose own controls draw the browser ring. No stop is hidden.
- **Touch:** iPhone 12 emulation (`hover: none`): forced `:hover` changes nothing on CTA, burger, cart and "add to cart"; `:active` still nudges 1px. (`Emulation.setEmulatedMedia` could not switch `hover` on desktop Chrome, so the device emulation was used.)
- **Reduced motion:** with `prefers-reduced-motion: reduce` `--duration-fast` is `0ms` and `transition-duration` of the CTA, cart and stepper is `0s`; without it, `0.15s`.
- **Opacity grep:** `opacity` is left only on `Button:disabled`, `QuantityStepper` aria-disabled (both `--opacity-disabled`), `Input` placeholder (`opacity: 1`) and a comment.
- **Not checked:** a real hover with a physical pointer was replaced by forced pseudo-states (hover transitions were not watched frame by frame); Safari / Firefox (`color-mix`, `translate` are baseline in current versions).
