# Task 5.3: Cart ("My Bag" popover) and add-to-cart

> Note (7.0): the working screenshots named in this file's Test report were removed from the repository in 6.0 (commit `de67a19`). They are still in git history: `git show de67a19^:tasks/screenshots/<file>`.

No own route: "My Bag" opens from the header cart icon on every page. Frames: Desktop `7:40` (shown over Why Miss Cupcake), Tablet `30:232`, Mobile `31:843`. Requires ADR-1 and ADR-3 from [05.0-architecture.md](05.0-architecture.md).

## What it shows (Desktop)

- Title "My Bag", close ×.
- Lines: thumbnail, "Carrot x 1", line price "$3.49"; separators between header, lines and total.
- "Total to pay" + subtotal ("$27.92" in Figma).
- Buttons: "CHECK OUT" (filled) → `/checkout`, "VIEW CART" (text) → `/checkout`.

## Behaviour

- Homepage "add to cart" adds the card's stepper quantity to the cart (ADR-1), then resets the stepper to 1 and briefly confirms (badge updates; optional short "Added" text, `aria-live`).
- Header cart button toggles My Bag (`aria-expanded`, `aria-controls`).
- My Bag is read-only (quantities change on `/checkout`).
- **Empty state** (not in Figma): "Your bag is empty" + link "Shop cupcakes" → `/#cupcakes`; "CHECK OUT" hidden. Keep it in the design's style.
- Closes on ×, Escape, outside click, route change; focus returns to the cart button.
- Mobile: follow the Mobile frame (`31:843`); if it is a full-width panel, make the page behind non-scrollable while open.

## Acceptance criteria

- [x] Adding from the Homepage updates the header badge immediately and survives a reload.
- [x] My Bag lists every cart line with the right name, thumbnail, `qty`, line total (`qty × $3.49`) and subtotal; numbers formatted as `$10.47`.
- [x] Figma scenario reproduces: add Carrot ×1, Red Velvet ×3, Mint Chip ×2, Pink strawberry ×2 → badge 8, total $27.92.
- [x] Empty state shown when the cart is empty; badge hidden.
- [x] Opens and closes with mouse and keyboard; Escape and outside click close it; focus handling as in ADR-3; `aria-expanded` reflects the state.
- [x] Popover position and size match Figma on Desktop/Tablet (anchored under the cart, right-aligned); Mobile matches `31:843`.
- [x] It never goes off-screen from 320 to 1920 and scrolls internally if there are many lines.
- [x] Manual test (agent, Chrome at 375 / 960 / 1440): run the Figma scenario above, compare with the frames, keyboard pass, console clean; **Test report** appended.
- [x] `yarn build`, `yarn lint`, `yarn test` pass.

## Test report

Date: 2026-10-12. Chrome (DevTools MCP) at 320, 375, 960, 1440. Screenshots: `tasks/screenshots/bag-{375,960,1440}.png`, `bag-empty-1440.png`. Reviewed by a separate reviewer agent; its findings (adding with the stepper at 0 still announced "Added", My Bag staying open after the same-page "Shop cupcakes" link, the mobile menu staying open under the bag, a repeated add not re-announced) are fixed.

**Done**
- **Cart state (ADR-1):** Jotai store in `src/features/cart/`; components only use `useCartLines / useCartCount / useCartSubtotal / useCartActions`. Only `{ id, qty }[]` is stored under `miss-cupcake:cart`; prices are integer cents (`UNIT_PRICE_CENTS = 349`) formatted by `Intl`. Stored data is cleaned on every read (unknown ids, non-positive or fractional quantities dropped, repeated ids merged, corrupt JSON gives an empty cart).
- **Tests:** `yarn test` runs 24 Vitest tests: pure cart functions (add, merge, decrease to 0 removes, no new lines from `setItemQty`, sanitising), atoms through `createStore()` (count, cents, joined lines, clear, independent stores), storage with a fake `localStorage` (saved cart, corrupt JSON, bad rows, write format, values from another tab) and price formatting.
- **Figma scenario in the browser:** Carrot 1, Red Velvet 3, Mint Chip 2, Pink strawberry 2 added with the real steppers and buttons: badge "Cart, 8 items", stored `[{carrot 1},{red-velvet 3},{mint-chip 2},{pink-strawberry 2}]`, My Bag lines "$3.49 / $10.47 / $6.98 / $6.98", total "$27.92". Steppers return to 1 after adding; the stepper can no longer go below 1 on Home; each add is announced through a `role="status"` line ("Added to cart").
- **Persistence:** after a reload the badge is right immediately (`getOnInit`); a `storage` event with `[{carrot 4},{nope 9}]` set the badge to 4 (unknown id ignored); `{broken` in storage gives "Cart, empty" and no badge. Console clean.
- **My Bag popover (ADR-3):** the cart button is a `<button>` with `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`; the panel is a non-modal `role="dialog"` labelled by "My Bag". On open focus goes to the close button. Escape and × close it and return focus to the cart button; a click outside closes it without moving focus; the cart button toggles it; any navigation or a followed link closes it.
- **Geometry vs Figma (card = frame minus the 12px baked shadow):** Desktop card at 939, 80, 460 x 707 (Figma 939, 80, 460 x 706); Tablet 450, 70, 460 x 707 (Figma 450, 70); Mobile 125, 62, 230 x 354 after the offset fix (Figma 125, 62, 230 x 353). Tablet and Desktop share one card design (as in Figma); lines, separators, total and buttons sit within 2px of the frames. Fonts use the existing cart tokens.
- **Empty state:** "Your bag is empty" and a "Shop cupcakes" button to `/#cupcakes`; no "Check out" / "View cart"; badge hidden.
- **Never off-screen:** at 320 x 500 with 11 lines the card stays inside the viewport (right edge 20px from the screen edge), the list scrolls inside and both buttons stay visible; no horizontal scroll.
- **Re-renders:** a cart change re-rendered `SiteHeader` but not `Home` (render counters, since React DevTools is not available).
- **Routes:** `/checkout` and `/checkout/payment` exist as placeholders, unknown paths show a 404 with a link to the shop.

**Remaining deviations**
- Figma has no hover or focus for the close button; the global focus ring is drawn around it (focus moves there on open).
- The card shadow is baked into the Figma image; the CSS shadow is an approximation. Card radius (12px, 6px on Mobile) is measured from that image.
- "View cart" has no Figma fill, so it is a new `text` variant of `Button` (purple label, no box).
- "Total to pay" on Mobile reuses the 10px line-name token (Figma: Lato 10 / 12).
- The Mobile frame is a 230px popover, not a full-width panel, so the page behind stays scrollable.
