# Task 6.1: "Registered completed": newsletter confirmation banner

Frames: Homepage Desktop `839:2`, Tablet `37:217`, Mobile `164:218`. The only difference from the normal Homepage is a **64px bar above the header**: Desktop `839:201` (text `839:203`, close icon `839:204`), Tablet `964:1`, Mobile `164:446` (text `164:445` on two lines, close `164:442`).

**Trigger (decided):** the footer newsletter form "Sugar up your Inbox". There is no account registration (Passcode in 5.5 is just a field).

## Before you start

- Read the banner text and colors from the nodes above (`get_design_context` or the REST API). They were not readable when this task was written (Figma quota). Fix typos per ADR-6.
- Compare `839:2` with `1:2` for any other difference (the first card `839:32` looks different); list what you find, don't build differences that are only Figma noise.

## Behaviour

- Footer form on **every page**: email validated with the same rule as Payment (`features/checkout/validation.ts`, reuse, don't copy). Invalid → error under the field (shared `Input error`), focus stays in the field.
- Valid "send": no network request. Store `{ subscribed: true }` in `localStorage` (`miss-cupcake:newsletter`, try/catch) — **never the email itself**. Clear the field.
- Then navigate to `/` (top of the page) and show the banner. On the Homepage itself: scroll to top and show the banner.
- Banner: in the page flow above the header (pushes content down by 64px, as in Figma, not overlaying it); text in a `role="status"` region so screen readers announce it; close × (`aria-label="Close"`) hides it and returns focus to the header's first link.
- Banner shows once per subscription: after close (or on the next visit) it doesn't come back. Subscribing again shows it again.
- Already subscribed users can still use the form (shows the banner again); no "already subscribed" state (not in the design).
- Component: `src/components/NoticeBar/` (props: message, onClose), reusable.

## Test report

Design data: Figma MCP and REST were both rate-limited (Starter plan, `Retry-After` ~4 days), so the nodes were read from the cached file JSON (`/tmp/file.json`, saved earlier from the REST API).

**Banner values (839:201 / 964:1 / 164:446):** bar 64px high, fill `#642C99` (`--color-primary`); text Lato Regular `#FBFACA` (`--color-on-primary`), 18/21.6 on Desktop and Tablet, 14/16.8 on Mobile in a 213px box, centred on the bar; close = 25px circle `#FCEFD2` at 20% opacity (`--color-surface`) with an 11px 1px-stroke `#FBFACA` cross, 30px from the right edge, top offset 20px. Text: "Registered completed successfully. We'll keep you up to date" (no typo to fix). New tokens: `--font-size-notice` (14 / 18) and `--line-height-notice` (1.2).

**Differences found between `839:2` and `1:2` (and the Tablet / Mobile pairs):**
- Real: only the bar. Everything else is at the same coordinates and the frame height is the same (6502 / 6959 / 9660).
- The bar sits at y=0 *on top of* the header (cart icon is at y=16 in both frames), so Figma overlays it, it does not push the content. This task asked for a push of 64px, which is what is built.
- Figma noise, not built: the first card `839:32` is split into a separate image + info group (same content and size as `940:5`); the nav "words" group is 22px vs 43px from the left (hand-placed); layer names / grouping.
- Mobile: the two lines come from a line break after "successfully."; built with `max-width: 213px` + `text-wrap: balance`, which breaks at the same place at 375 (checked); at 320 it wraps to three lines inside the 64px bar.

**Chrome, 1440 / 960 / 375 (+320):**
- Invalid email (`nope`, empty) on Our Story: "Enter a valid email address." / "This field is required." under the field, `aria-invalid="true"`, `aria-describedby` points at the message, focus stays in (or returns to) the field after clicking "send", nothing stored, URL unchanged. The error clears when typing.
- Valid email from Our Story: URL `/`, scrollY 0, banner above the header (bar 64px, header top at 64), field cleared, no non-GET request and no request containing the email; `localStorage` holds only `miss-cupcake:newsletter = {"subscribed":true}`.
- Valid email from Home scrolled to the footer: scrolls to y=0, banner shown. From Why Miss Cupcake: navigates to `/`, banner shown.
- Banner text centre = bar centre at all widths; × 25x25, 19.5px from the top; the right offset measured 32px and was then set to Figma's 30px (CSS only, not re-measured); font 14/16.8 (Mobile) and 18/21.6 (Tablet, Desktop); no horizontal scroll at 320 / 375 / 960 / 1440.
- Close with Enter / Space: banner removed; focus goes to "Shop" (960, 1440) or to the Menu button (375, where the nav links are hidden). Header moves up 64px.
- Reload after closing: no banner. Subscribing again: banner shown again.
- Console: no errors or warnings in any run.
- Not checked: a real screen reader (the `role="status"` region is mounted empty and filled on the next frame so it is announced).
