# Task 5.5: Check out – Payment (delivery and form)

Route `/checkout/payment`. Frames: Desktop `148:184`, Tablet `30:234`, Mobile `31:845`. Requires ADR-1, ADR-4, ADR-6 from [05.0-architecture.md](05.0-architecture.md). No real payment.

## What it shows (Desktop)

- Hero "Check out" (same as 5.4), link "‹ Back to My cart" → `/checkout`.
- **Delivery type**, radio group:
  - Regular Package, $0: "Complete your order and we'll bring it to your door."
  - Birthday Package, $9.90: "Fun birthday cupcake packages with candles and assorted party favors."
  - Valentine's day Package, $12.90: "The perfect delectable treat on the year's most romantic day…"
- "Total to pay" (after delivery).
- **To be delivered to**: First name, Last name, Email address, Passcode (+ hint "* Must be 10 or more characters").
- **Address**: Street, City, Postcode, Entrance.
- **Contact**: Recipient's Name, Phone No.
- **Payment**: Credit card No., Expiration date (`MM \ YYYY`, two inputs with a "\" divider), Card holder, CVV.
- "Total to pay" + "PLACE ORDER" → opens Confirmed (Task 5.6).
- Mobile frame: check it for extra UI (tokens mention progress bars on Mobile Payment); build it if present.

## Decisions (defaults)

- Total = cart subtotal + delivery price; updates when the radio changes. Regular is selected by default.
- Passcode is **just a field** (no registration): `type="password"`, min 10 characters. Not stored anywhere.
- Radio group: native `<input type="radio">` in a `<fieldset>` + `<legend>` ("Delivery type"), custom look with the Figma radio SVGs.
- Each form block is a `<fieldset>` with its title as `<legend>`.

### Validation rules

| Field | Rule | `autocomplete` / `inputmode` |
|---|---|---|
| First name, Last name, Recipient's Name, Card holder | required, 2–50 letters/spaces/'- | `given-name`, `family-name`, `name`, `cc-name` |
| Email address | required, valid email | `email` |
| Passcode | required, ≥ 10 characters | `new-password` |
| Street, City | required | `address-line1`, `address-level2` |
| Postcode | required, UK format (sample "WC1N 3PJ"), case-insensitive | `postal-code` |
| Entrance | optional, ≤ 10 characters | |
| Phone No. | required, 7–15 digits, may start with `+`, spaces allowed | `tel`, `inputmode="tel"` |
| Credit card No. | required, 13–19 digits, **Luhn** check, shown in groups of 4 | `cc-number`, `inputmode="numeric"` |
| Expiration date | MM 01–12, YYYY current year to +15; not in the past | `cc-exp-month`, `cc-exp-year` |
| CVV | 3–4 digits | `cc-csc`, `inputmode="numeric"` |

Test card for manual checks: `4242 4242 4242 4242`.

## Acceptance criteria

- [ ] Empty cart → redirect to `/checkout`.
- [ ] Delivery radio works with mouse and arrow keys; total updates (e.g. $27.92 + $9.90 = $37.82).
- [ ] Every field has a visible label, the `autocomplete` from the table, and the right keyboard on mobile (`inputmode`).
- [ ] Validation on blur and on submit per the table; error text under the field (`Input error`), `aria-invalid`, `aria-describedby`; first invalid field gets focus on submit.
- [ ] Valid form → Confirmed modal (5.6); invalid → stays, no modal.
- [ ] Card number, CVV, expiration and passcode are never sent, stored (local/sessionStorage) or logged: checked in DevTools Application and Network tabs.
- [ ] Non-sensitive fields and delivery choice survive a reload (`sessionStorage`).
- [ ] Copy has fixed typos (ADR-6).
- [ ] Layout matches Desktop/Tablet/Mobile frames (two columns on Desktop/Tablet, one on Mobile).
- [ ] Unit tests for validators (Luhn, postcode, expiry in the past, phone).
- [ ] Manual test (agent, Chrome at 375 / 960 / 1440): submit empty, fix fields one by one, change delivery, submit valid with the test card, keyboard-only run, console clean; **Test report** appended.
- [ ] `yarn build`, `yarn lint`, `yarn test` pass.
