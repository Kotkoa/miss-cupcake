# Task 5.4: Check out (cart review)

Route `/checkout`. Frames: Desktop `7:400`, Tablet `30:233`, Mobile `31:844`. Requires the cart from Task 5.3.

## What it shows (Desktop)

- Hero: "Check out", subtitle "Complete your order and we'll bring it to your door.", donut images (decorative).
- Cart table: thumbnail, name, `QuantityStepper`, line total; one row per cart line.
- Separator, "Total to pay" + subtotal, button "PLACE ORDER" → `/checkout/payment`.
- Footer on the purple band.

## Decisions (defaults)

- Rows are a list (`<ul>`), not a `<table>`: one row per item, no column headers in the design.
- Stepper changes the cart (ADR-1) live; line and total recalculate instantly.
- Decreasing to 0 removes the line (no confirm dialog). No separate "remove" button (not in the design).
- **Empty cart** (not in Figma): message + link to `/#cupcakes`; "PLACE ORDER" hidden. Direct visits to `/checkout/payment` with an empty cart redirect here.
- Button text stays "PLACE ORDER" as in Figma, even though it leads to the payment step.

## Acceptance criteria

- [x] `/checkout` lists all cart lines from `useCartLines()` with thumbnail, name, stepper and line total; total matches the sum.
- [x] Figma scenario (Carrot 1, Red Velvet 3, Mint Chip 2, Pink strawberry 2) renders as in `7:400`, total $27.92.
- [x] Stepper: + / − update the line, total, header badge and My Bag; going to 0 removes the line; changes survive reload.
- [x] Stepper buttons have item-specific `aria-label`s (e.g. "Increase quantity of Carrot"); the total is announced politely (`aria-live`).
- [x] Empty state works; "PLACE ORDER" is a link to `/checkout/payment` only when the cart is not empty.
- [x] Layout matches Desktop/Tablet/Mobile frames; rows don't break at 320.
- [x] Manual test (agent, Chrome at 375 / 960 / 1440): Figma scenario, change quantities, empty the cart, keyboard pass, console clean; **Test report** appended.
- [x] `yarn build`, `yarn lint`, `yarn test` pass.
